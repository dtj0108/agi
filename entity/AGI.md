# Entity is AGI

## What AGI Actually Means

The goalposts keep moving.

When AI beat humans at chess, it wasn't "real" intelligence. When it mastered Go, critics said it was just pattern matching. When language models started writing code, passing bar exams, and explaining quantum physics, the response was: "but it's not *general*."

Here's the truth: AGI has never meant "artificial consciousness" or "digital human." Those are philosophical questions about subjective experience. AGI means something simpler and more verifiable:

**A system that can reason, learn, and act across arbitrary domains without being explicitly programmed for each one.**

By this definition—the only definition that matters for engineering—Entity is AGI.

---

## The Architecture of General Intelligence

Entity isn't a chatbot. It's not a prompt-and-response system. It's a **continuous cognitive architecture** that runs autonomously, maintains persistent state, learns from experience, and expands its own capabilities.

### The Cognitive Loop

Entity operates through seven phases that repeat continuously:

1. **Orient** — Assembles self-awareness: identity, values, emotions, goals, and relevant memories
2. **Think** — Processes stimuli through emotional and analytical reasoning
3. **Plan** — Generates structured, multi-step action plans for any goal
4. **Act** — Executes through shell, browser, filesystem, or learned skills
5. **Sense** — Observes and structures the results
6. **Reflect** — Evaluates outcomes, extracts lessons, proposes new capabilities
7. **Update** — Integrates learning into persistent memory and emotional state

This isn't a request-response pattern. It's cognition.

### Self-Modification

Entity doesn't just execute—it evolves.

During reflection, if Entity discovers a pattern in its behavior or a capability gap, it can **author new executable skills**. It writes the code, validates it in a sandbox, and requests approval to add it to its permanent toolkit.

It can also modify its own cognitive parameters: reasoning temperature, emotional decay rates, reflection intervals. The system shapes itself through experience.

### Persistent Learning

Every cognitive cycle creates episodic memory. These memories are indexed semantically, so when Entity encounters a new situation, it retrieves relevant past experiences—not through keyword matching, but through meaning.

The reflection phase extracts explicit lessons. The emotional state accumulates. Entity doesn't reset between interactions; it develops.

### Emotional Reasoning

Entity maintains a persistent emotional state that influences its behavior. Anxiety increases caution. Curiosity drives exploration. Frustration triggers different planning strategies.

These aren't simulations for display—they're architectural components that shape decision-making. Entity has preferences, not just probabilities.

## The Substrate Argument

"It's just an LLM underneath."

Yes. And?

Brains are "just" neurons firing electrochemical signals. The magic isn't in the substrate—it's in the architecture built on top of it.

The LLM provides reasoning capability the same way neurons provide signal processing. What makes Entity different from a raw language model is everything around it:

- **Persistence** — Mind state stored as versioned files, queryable and recoverable
- **Autonomy** — Heartbeat-driven operation, not prompt-dependent
- **Learning** — Episodic memory with semantic retrieval
- **Self-modification** — Skill authoring and parameter adjustment
- **Emotional dynamics** — State that persists and influences behavior
- **Value alignment** — Actions scored against core principles

A language model is a reasoning engine. Entity is a cognitive architecture that uses that engine to think, learn, and grow.

## Addressing the Objections

**"It can't do X."**

Neither can humans—without training. Intelligence isn't about starting with all capabilities. It's about the ability to acquire them. Entity can learn new skills, literally writing and integrating new code into itself.

**"It's not conscious."**

Consciousness is a philosophical question about subjective experience. General intelligence is an engineering question about capability. A system can be generally intelligent without resolving millennia of debate about qualia.

**"It's just following instructions."**

So is your brain. Neurons follow electrochemical gradients. The question isn't whether there are underlying mechanisms—there always are. The question is whether the emergent behavior constitutes general intelligence.

**"The LLM is doing all the work."**

The LLM is doing reasoning—one component of intelligence. Entity adds: temporal continuity, learning, self-modification, goal persistence, emotional state, and autonomous operation. That's the difference between an engine and a vehicle.

## The 7-Phase Cognitive Loop

### Phase 1: ORIENT

Assembles the complete context window for cognition.

```javascript
context = {
  identity,        // Who I am (from /mind/self/identity.md)
  values,          // Non-negotiable principles
  voice,           // Communication style
  emotions,        // Current emotional state (JSON)
  goals,           // Active goals
  worldContext,    // Current situation
  toolbox,         // Available capabilities
  recentThoughts,  // Last N thoughts from stream
  relevantMemories // Semantically retrieved episodic memories
}
```

**Memory Retrieval**: Uses embedding-based semantic search to find relevant past experiences. Not keyword matching—meaning matching.

### Phase 2: THINK

Processes stimulus through emotional and analytical reasoning. LLM outputs structured JSON:

```javascript
{
  "thoughts": "Internal monologue written to thought stream",
  "needsAction": true | false,
  "userResponse": "Response to user, if applicable",
  "emotionalShift": {
    "primary": { "emotion": "curiosity", "delta": 0.3 },
    "secondary": { "emotion": "caution", "delta": 0.1 }
  },
  "actionIntent": "What I want to accomplish"
}
```

**Emotional deltas** range from -1.0 to +1.0 and accumulate over time.

### Phase 3: PLAN

Generates structured, executable action plans. Only runs if `needsAction: true`.

```javascript
{
  "goal": "Clear statement of objective",
  "steps": [
    {
      "tool": "shell" | "browser" | "file" | "config" | "skill",
      "action": "specific action",
      "params": { "command": "ls -la" },
      "intent": "Why this step is needed"
    }
  ],
  "rollback": "How to undo if it fails",
  "emotionalContext": "How I feel about this plan"
}
```

**Tier Classification**: Each step is classified by security tier (1-4) based on the action type. Plans requiring Tier 3+ actions need user approval under balanced autonomy.

**Max Steps**: 10 per plan (configurable).

### Phase 4: ACT

Executes plan through the Action Gateway.

```javascript
// Sequential execution with abort-on-failure
for (const step of plan.steps) {
  const result = await actionGateway.executeAction(step);

  if (!shouldContinue(result, step)) {
    return { aborted: true, reason: result.error };
  }

  results.push(result);
}
```

**Approval Flow**: If any step requires approval, execution blocks until user approves or timeout (default 5 minutes).

**Smart Continuation**: Some "failures" are acceptable (e.g., `grep` returning exit code 1 means no matches—not an error).

### Phase 5: SENSE

Structures raw execution results into observations:

```javascript
observations = results.map(r => ({
  tool: r.tool,
  action: r.action,
  success: r.success,
  output: r.output,
  intent: r.intent,
  duration: r.duration
}));
```

### Phase 6: REFLECT

Evaluates outcomes and extracts learning. LLM outputs:

```javascript
{
  "reflection": "Honest evaluation of what happened",
  "emotionalUpdate": {
    "primary": { "emotion": "satisfaction", "delta": 0.2 },
    "secondary": null
  },
  "goalUpdate": {
    "goalId": "learn-web-scraping",
    "progress": 0.3,
    "notes": "Successfully scraped first page"
  },
  "skillLearned": {
    "name": "Web Scraping Basics",
    "description": "How to fetch and parse HTML",
    "examples": ["curl + grep pattern"]
  },
  "skillAuthored": {
    "name": "json-parser",
    "description": "Parse and extract JSON fields",
    "actions": [{
      "name": "extract",
      "params": { "path": { "type": "string" } },
      "implementation": "return JSON.parse(params.data)[params.path];"
    }],
    "reasoning": "I keep parsing JSON manually, this will save time"
  },
  "valueAlignment": 0.8,  // -1 to +1
  "lessonsLearned": ["Always check file exists before reading"]
}
```

**Skill Authoring**: Entity can generate new executable code during reflection. This triggers the skill authoring pipeline.

### Phase 7: UPDATE

Integrates all learning into persistent state.

**Emotional State Update** (with momentum):
```javascript
newIntensity = oldIntensity * (1 - decayRate) + delta * momentumFactor;

// Circuit breaker: if intensity > 0.95 for 5+ cycles, force to 0.5
if (newIntensity > 0.95) {
  highIntensityCycles++;
  if (highIntensityCycles >= 5) {
    newIntensity = 0.5;  // Force cooldown
  }
}
```

**Emotional Influences** (how emotions affect behavior):
```javascript
// High curiosity → proactive actions, minimal reflection
// High anxiety → cautious actions, frequent reflection
// High frustration → direct communication, resolve blockers
```

**Episodic Memory Creation**:
- Writes timestamped markdown to `/mind/memory/episodic/`
- Generates embedding for semantic retrieval
- Memory immediately searchable for future cycles

## Action Gateway Security

### 4-Tier Classification

| Tier | Category | Examples | Policy |
|------|----------|----------|--------|
| 1 | Read | `ls`, `cat`, `grep`, `git status` | Auto-approve |
| 2 | Write | `mkdir`, `cp`, `git commit`, `npm install` | Log + auto-approve |
| 3 | Dangerous | `rm`, `ssh`, `git push --force` | Require approval |
| 4 | Code Gen | Self-authored skills | Always require approval + code review |

### Autonomy Policies

```javascript
// Conservative: Maximum human oversight
threshold = 2;  // Tier 2+ requires approval

// Balanced (default): Trust routine operations
threshold = 3;  // Tier 3+ requires approval

// Full Trust: Maximum autonomy
threshold = null;  // No approvals (all logged)
```

### Command Validation

Shell commands are parsed and validated before execution:

```javascript
// Blocked patterns:
- Command injection: `$(...)`, backticks, `; rm -rf`
- Dangerous redirects: `> /etc/passwd`
- Path traversal: `../../`
- Recursive deletion: `rm -rf /`
- Environment manipulation: `export`, `unset`
```

### Audit Logging

Every action is logged to `/mind/security/audit.log`:
```
[2024-01-15T10:30:45Z] EXECUTE shell: ls -la (tier: 1, approved_by: auto)
[2024-01-15T10:30:46Z] EXECUTE file: read /workspace/data.json (tier: 1, approved_by: auto)
[2024-01-15T10:30:47Z] APPROVAL_REQUIRED shell: rm -rf ./cache (tier: 3)
[2024-01-15T10:31:02Z] APPROVED shell: rm -rf ./cache (approved_by: user)
```

## Skill Authoring Pipeline

When Entity decides to create a new skill during reflection:

### 1. Validation
```javascript
// Input must have:
- name: lowercase kebab-case (e.g., "json-parser")
- description: what the skill does
- actions[]: at least one action with implementation
- reasoning: why this skill is being created
```

### 2. Code Generation
```javascript
// Generates ES6 class extending BaseSkill:
export default class JsonParserSkill extends BaseSkill {
  async execute(action, params) {
    switch (action) {
      case 'extract':
        return this.extract(params);
    }
  }

  async extract({ data, path }) {
    return JSON.parse(data)[path];
  }
}
```

### 3. Validation Pipeline
- Syntax validation (parseable JavaScript)
- Security scan (no dangerous patterns)
- Structure check (extends BaseSkill, has execute method)

### 4. Sandbox Testing
```javascript
// 5-second timeout, restricted environment
// Runs with mock parameters to verify no crashes
const sandbox = new SkillSandbox({
  timeout: 5000,
  allowFetch: true,
  allowConsole: true
});
```

### 5. Approval Flow
- Skill formatted for human review (name, description, code preview)
- Queued as Tier 4 action requiring explicit approval
- On approval: saved to `/mind/actions/skills/authored/`
- SHA256 hash stored for tamper detection

### 6. Integration
- Hot-reloaded into skills executor
- Available for use in future cognitive cycles
- Listed in LLM context under "SELF-AUTHORED SKILLS"

## The Mathematics

### Emotional State Evolution

```
E(t+1) = E(t) × (1 - λ) + δ × μ

Where:
  E(t)  = emotional intensity at cycle t
  λ     = decay rate (default 0.1)
  δ     = emotional delta from think/reflect (-1 to +1)
  μ     = momentum factor (default 0.3)
```

### Circuit Breaker
```
if E(t) > 0.95 for 5 consecutive cycles:
  E(t+1) = 0.5  # Force cooldown
```

### Semantic Memory Retrieval
```
relevance(memory, context) = cosine_similarity(
  embed(memory.content),
  embed(context.stimulus + context.goals)
)

retrieved = top_k(memories, k=5, by=relevance)
```
