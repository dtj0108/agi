================================================================================
ENTITY — ONBOARDING & BOOTSTRAP SPEC
================================================================================

This spec covers ONLY the onboarding system: installer script, interactive
wizard, mind initialization, daemon setup, and first boot. Hand this to
Claude Code to build the bootstrap before anything else.

Dependency: @clack/prompts for the terminal wizard UI.


================================================================================
1. INSTALLER SCRIPT (scripts/install.sh)
================================================================================

One-liner: curl -fsSL https://entity.dev/install.sh | bash

What it does:
1. Detect OS (macOS, Linux, WSL2)
2. Check for Node.js 20+ — if missing, offer to install via nvm
3. Check for Git — if missing, offer to install (brew on mac, apt on linux)
4. Clone the entity repo (or npm install -g entity@latest)
5. Run npm install
6. Launch the onboarding wizard: node scripts/onboard.js

Keep it simple. One file. Works on a fresh Mac Mini or a fresh Ubuntu VPS.
No Docker required for local installs.


================================================================================
2. ONBOARDING WIZARD (scripts/onboard.js)
================================================================================

Interactive terminal wizard using @clack/prompts. 7 phases. Writes config
file + initializes all mind files + starts the entity for the first time.

Also supports --non-interactive mode with flags for scripting:
  node scripts/onboard.js --non-interactive \
    --user-name "Drew" \
    --entity-name "Atlas" \
    --llm-provider anthropic \
    --llm-api-key "sk-ant-..." \
    --autonomy balanced \
    --deploy local


────────────────────────────────────────────────────────────────────────────────
PHASE 1: WELCOME
────────────────────────────────────────────────────────────────────────────────

- ASCII art logo (keep it clean, 5-6 lines max)
- One paragraph: "You're about to create an entity — a persistent AI with
  its own mind, memory, emotions, and the ability to act on your computer.
  This wizard will set everything up."
- Security notice: "This entity will have access to your shell, browser,
  and files within a sandboxed workspace. You control what it can do."
- Confirm: "Ready to begin?" → yes/no


────────────────────────────────────────────────────────────────────────────────
PHASE 2: MEET THE USER
────────────────────────────────────────────────────────────────────────────────

"Let's start with you. The entity needs to know who it's working with."

Questions (in order):

1. "What's your name?"
   → text input, required

2. "What should the entity call you?"
   → text input, default = first name from above

3. "What do you do?"
   → text input, placeholder: "e.g. founder building a SaaS product,
     software engineer at Google, student studying CS..."

4. "What are you working on right now?"
   → text input, placeholder: "e.g. launching my startup, learning React,
     automating my workflow..."

5. "How do you like to communicate?"
   → single select:
     - Casual & direct (default)
     - Professional but friendly
     - Formal
     - Match my energy

6. "What do you want the entity to help with?"
   → multi select (pick all that apply):
     - Coding & development
     - Research & learning
     - File & project management
     - Web browsing & automation
     - Thinking partner / brainstorming
     - Everything

7. "Anything else the entity should know about you?"
   → text input, optional, placeholder: "hobbies, preferences, pet peeves,
     anything..."

Store all answers in a userProfile object passed to Phase 6.


────────────────────────────────────────────────────────────────────────────────
PHASE 3: NAME THE ENTITY
────────────────────────────────────────────────────────────────────────────────

"Now let's set up the entity itself."

1. "What do you want to name your entity?"
   → text input, default: "Entity"

2. "Describe its personality in a few words"
   → text input, default: "curious, direct, thoughtful"
   → placeholder: "e.g. witty and sharp, calm and methodical, warm and
     enthusiastic..."

3. "How autonomous should it be?"
   → single select:
     - Conservative — asks before any non-read action
     - Balanced — reads and simple writes autonomous, rest asks (RECOMMENDED)
     - Full trust — only dangerous/destructive actions ask

Store as entityProfile object.


────────────────────────────────────────────────────────────────────────────────
PHASE 4: LLM SETUP
────────────────────────────────────────────────────────────────────────────────

"The entity needs a brain. Choose an LLM provider."

1. "Which LLM provider?"
   → single select:
     - Anthropic (Claude) — recommended, supports prompt caching
     - OpenAI (GPT)
     - OpenRouter — access any model through one API
     - Ollama (local) — free, private, runs on your machine
     - Custom endpoint — any OpenAI-compatible API

2. Based on selection, prompt for:

   ANTHROPIC:
     - API key: text input (masked)
     - Model: select → claude-sonnet-4-5 (recommended) / claude-opus-4-5 /
       claude-haiku-4-5
     - Set: api = "anthropic-messages", baseUrl = "https://api.anthropic.com/v1"
     - Set: promptCaching = true

   OPENAI:
     - API key: text input (masked)
     - Model: select → gpt-4o (recommended) / gpt-4o-mini / gpt-5
     - Set: api = "openai-completions", baseUrl = "https://api.openai.com/v1"

   OPENROUTER:
     - API key: text input (masked)
     - Model: text input, default "anthropic/claude-sonnet-4-5"
     - Set: api = "openai-completions", baseUrl = "https://openrouter.ai/api/v1"

   OLLAMA:
     - Base URL: text input, default "http://127.0.0.1:11434/v1"
     - Model: text input, default "llama3.3:70b"
     - Set: api = "openai-completions", apiKey = "ollama"

   CUSTOM:
     - Base URL: text input, required
     - API key: text input (masked), optional
     - Model: text input, required
     - API format: select → OpenAI-compatible / Anthropic-compatible

3. Test the connection:
   - Send a simple completion request: "Respond with the word 'hello'"
   - Show spinner: "Testing LLM connection..."
   - On success: "✓ Connected to [model] successfully"
   - On failure: Show error, offer to retry or pick different provider

Store as llmConfig object.


────────────────────────────────────────────────────────────────────────────────
PHASE 5: DEPLOYMENT
────────────────────────────────────────────────────────────────────────────────

"Where will the entity live?"

1. "Deployment type?"
   → single select:
     - This machine (local) — runs as a background daemon
     - Docker container — for VPS or isolated deployment
     - Manual — just give me the start command

2. If LOCAL:
   - Auto-detect OS
   - "Install as a background service that starts on boot?"
     → yes/no
   - If yes on macOS:
     Generate ~/Library/LaunchAgents/com.entity.daemon.plist
     Contents:
       Label: com.entity.daemon
       ProgramArguments: [node path, src/index.js path]
       WorkingDirectory: project root
       RunAtLoad: true
       KeepAlive: true
       StandardOutPath: ~/.entity/logs/stdout.log
       StandardErrorPath: ~/.entity/logs/stderr.log
     Run: launchctl load <plist path>

   - If yes on Linux:
     Generate ~/.config/systemd/user/entity.service
     Contents:
       [Unit] Description=Entity AI Daemon
       [Service] ExecStart=node <src/index.js path>
         WorkingDirectory=<project root>
         Restart=always
       [Install] WantedBy=default.target
     Run: systemctl --user enable entity && systemctl --user start entity

3. If DOCKER:
   - Generate docker-compose.yml at project root:
     version: '3.8'
     services:
       entity:
         build: .
         volumes:
           - ./mind:/app/mind
           - ./entity-workspace:/app/entity-workspace
           - ./config:/app/config
         ports:
           - "3000:3000"
           - "3001:3001"
         restart: unless-stopped
         environment:
           - LLM_API_KEY=${LLM_API_KEY}
   - Generate Dockerfile:
     FROM node:20-slim
     WORKDIR /app
     COPY package*.json ./
     RUN npm ci --production
     COPY . .
     RUN npx puppeteer browsers install chrome
     CMD ["node", "src/index.js"]
   - "Build and start now?" → yes/no
   - If yes: docker-compose up -d --build

4. If MANUAL:
   - Just print: "Run 'node src/index.js' or 'npm start' to start the entity."

Store as deployConfig object.

────────────────────────────────────────────────────────────────────────────────
PHASE 7: FIRST BOOT
────────────────────────────────────────────────────────────────────────────────

"Waking up [entityName]..."

1. Start the entity process (or daemon if Phase 5 installed one)

2. Trigger the first cognitive cycle with stimulus:
   {
     type: 'self_initiated',
     content: 'I have just been created by [callName]. I should orient
       myself — read my mind files, understand who I am, learn about
       [callName], and explore what I can do on this machine.'
   }

3. Stream the entity's first thoughts to the terminal in real time.
   Use @clack/prompts to show a live updating section as the entity
   writes to thoughts/stream.md.

4. The entity should (via its cognitive loop):
   a. ORIENT — read self.md, state.json, active.md, context.md, toolbox.md
   b. THINK — process the stimulus, write first real thoughts to stream.md
   c. PLAN — maybe plan to explore the filesystem (Tier 1, autonomous)
   d. ACT — optionally run `ls` or `whoami` to learn about its environment
   e. SENSE — observe the results
   f. REFLECT — write first reflection
   g. UPDATE — update world/context.md with what it learned

5. The entity's first response to the user should:
   - Acknowledge its own existence ("I'm [entityName]. I just woke up.")
   - Reference something about the user ("You mentioned you're working on
     [project] — I'd like to learn more about that.")
   - Express genuine curiosity
   - Be in the voice/style configured in Phase 2-3

6. Display: "[entityName] is alive. Type a message or let it think."

7. Drop into interactive CLI mode (or print WebSocket URL if headless)


================================================================================
POST-ONBOARDING CLI COMMANDS
================================================================================

These should be registered as CLI commands (add a bin entry in package.json
or use the interface/cli.js module):

  entity start           Start the daemon
  entity stop            Stop the daemon
  entity restart         Restart the daemon
  entity status          Show: emotional state, active goals, cycle count,
                         uptime, LLM provider, last action
  entity chat            Interactive CLI conversation
  entity doctor          Health check:
                         - Mind files exist and are valid? ✓/✗
                         - Git repo healthy? ✓/✗
                         - LLM reachable? ✓/✗
                         - Daemon running? ✓/✗
                         - Workspace writable? ✓/✗
  entity logs            Show recent thoughts (last 20 stream entries)
  entity logs --follow   Tail thoughts/stream.md in real time
  entity thoughts        Alias for entity logs
  entity goals           Show active goals
  entity emotions        Show current emotional state
  entity rollback <hash> Rollback /mind/ to a git commit
  entity history         Show git log for /mind/ (entity's cognitive history)
  entity reset           Factory reset — wipe mind, re-run onboard
                         (requires confirmation: "This will erase all of
                         [entityName]'s memories. Are you sure?")
